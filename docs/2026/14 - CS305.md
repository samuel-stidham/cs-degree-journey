| Category | Value |

**Course Description:**
Through the analysis of advanced security concepts, students will learn how to develop secure code that complies with security testing protocols. In addition to exploring and implementing security concepts through code, students will also learn why and how to apply encryption technologies and techniques to communicate securely.

---

## Key Topics & Concepts

This course reads *Iron-Clad Java: Building Secure Web Applications* across Modules One through Six, returning to several chapters more than once. Modules One and Two set up the Java toolchain and static testing, and Module Three submits Project One. Modules Four through Six turn to ciphers, checksums, certificates, and vulnerability reporting ahead of the Project Two submission in Module Seven. Topic summaries will be added as the course progresses.

* **Software Security Attacks & Toolchain Setup:** Module One, Chapters 1 and 10. The Software Security Attacks discussion, an Eclipse with Java install, a non-graded static testing tool integration, and the course quiz.
* **Code Review & Static Testing:** Module Two, Chapters 3 and 7. The Code Review and Mitigation Plan written assignment, the Static Testing coding assignment, and a first look at Project One.
* **Project One:** Module Three revisits Chapters 1, 3, 7, and 10 for the Project One submission, followed by the Reflection journal.
* **Algorithm Ciphers:** Module Four, Chapters 6 and 8. A first look at Project Two and the Algorithm Ciphers written assignment.
* **Checksums & Certificates:** Module Five, Chapter 6, with the Checksum Verification and Certificate Generation coding assignments.
* **Vulnerability Reporting:** Module Six, Chapter 10, with the Modifying Vulnerability Reporting coding assignment ahead of the Project Two submission.
* **Foundational Competencies:**
  * **CS-30412:** Analyze how advanced security concepts are applied to develop secure code.
  * **CS-30413:** Design and implement code that complies with software security testing protocols.
  * **CS-40414:** Write secure communications through the application of current encryption technologies and techniques.

## Discussion Work & Academic Themes

The course's one graded discussion, Software Security Attacks, falls in Module One.

1. **Software Security Attacks**
    * **Focus:** Introduced professional background and interests, then analyzed a news article on a software security attack. Detailed over fourteen years in software engineering and a current Senior Software Engineer role. Much of that work has been public-facing software where security is critical, with OWASP's Top Ten as a regular release check. Outside work, named Scandinavian folklore fiction such as The Witcher, plus games from Factorio to the Dragon Quest series. Mentioned a Minecraft resource pack in progress that turns carved pumpkins into cat-like jack-o'-lanterns, for Java and Bedrock 1.21 and later.
    * **Analysis:** Chose a BankInfoSecurity report on a Government Accountability Office audit of the U.S. electric grid (Venkat, 2019). The audit covered the Department of Energy and the Federal Energy Regulatory Commission, the two federal bodies responsible for grid cybersecurity. GAO published the report in August 2019 and released it on September 25, 2019 (U.S. Government Accountability Office, 2019). The article also described a March 2019 attempted denial-of-service attack that probed firewall weaknesses at a U.S. utility. GAO's core finding was that the grid grows easier to attack as adversaries improve. Industrial control systems once ran air-gapped on proprietary hardware. They now use standard IT protocols, connect to the internet, accept remote access, and sit beside cheap IoT devices (Venkat, 2019). Each change widened the attack surface, while DOE's plans leaned on grid assessments from the 1980s. Named the threat actors as nation-states, criminal groups, terrorists, hacktivists, and malicious insiders. Grouped the attacks into three kinds. IoT botnets switch compromised devices on in sync to unbalance generation against consumption. Denial of service targets the utility's network, as the March probe attempted. Planted malware causes outages, which has already happened in Ukraine (Venkat, 2019). Behind them sit weak remote access controls, unpatched edge devices, supply chain exposure, and thin staffing, funding, and threat intelligence (Venkat, 2019).
    * **Takeaway:** Traced the protections back to each vulnerability. GAO's main recommendation to FERC was the NIST Cybersecurity Framework and its five functions: identify, protect, detect, respond, and recover (U.S. Government Accountability Office, 2019). In practice that means knowing which control systems are reachable from outside and locking down every remote connection. Security gets designed in from the start, and supply chain controls cover the hardware entering a plant (Venkat, 2019). The March 2019 probe showed why patching matters, since a firewall on current firmware gives an attacker nothing to find. Closed on the gap in sharing classified threat intelligence with operators, and on the observation that the controllers never got weaker. They got connected, and the surrounding software was never built for hostile traffic.
